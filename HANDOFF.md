## 2. Идея продукта

Каждая тема ЕНТ = видеоурок в стиле 3Blue1Brown (Manim) + 12–15 задач под видео + пробник по теме + книга-конспект в подарок + повторение по схеме **1-3-7-10-14-30-60 дней** (карточки как в Anki). Напоминания о повторении приходят в Telegram. Интерфейс на русском и казахском (казахский — полноценный, не автоперевод). Цитаты на экранах — только казахских писателей.

Бренд: зелёный `#2BC98F`, чёрный `#0C0E0D`, белый; стеклянные («liquid glass») карточки, ощущение как у Apple. Не менять дизайн-токены в `app/globals.css` и `tailwind.config.ts` без явной задачи.

Пока без голоса в видео (только субтитры): ИИ-озвучку добавим, когда владелец купит подписки (ElevenLabs/Higgsfield и т. д.). Агенты поиска хуков и раскадровки отложены.

### «Повторить сегодня» (сделано 18 ноября)

- Страница `/review` (`app/[locale]/(app)/review/page.tsx`, `components/review/ReviewQueue.tsx`): список книг, которые пора повторить, прогресс «Повторено X из N», у каждой книги — «Повторение n из 7» и ряд 1-3-7-10-14-30-60 с подсветкой текущего шага. «Начать повторение» открывает тренажёр карточек по очереди; после книги кнопка «Следующая книга». Книги без карточек ведут на страницу книги (старый вариант с тремя кнопками) — в очереди они считаются «не пройденными карточками».

- Вход: оранжевая кнопка «Повторить сегодня · N» под кольцами на «Сегодня» и кнопка в блоке «Повторить сегодня» библиотеки. В меню страницу не добавляли (экраны без лишнего). Подписи: `review.*`, `today.reviewCta`, `cards.next` (казахский — черновик Claude).
- Общие подписи тренажёра вынесены в `lib/cards/labels.ts` (страница книги и очередь).
- Проверено глазами на 390 px с «подстроенной» cookie (две книги к повторению); сам зачёт «в срок» покрыт юнит-тестами расписания.

### Как устроен режим без базы (сделано 18 ноября)
- Переключатель: `NEXT_PUBLIC_DATA_MODE=local` (пусто или `supabase` — боевой режим). Код: `lib/data-mode.ts`.
- Данные ученика (книги, график повторений, сколько повторено сегодня, настройки: цель в день, дата ЕНТ, целевой балл, язык) лежат в **одной cookie браузера** `alemprep-local-v1` (`lib/local/state.ts`, компактный base64url-JSON, лимит ~3,6 КБ ≈ 50 книг). Cookie, а не `localStorage`, потому что серверные страницы читают её сами и рисуют готовый HTML; менять её могут только server actions (`lib/local/store.ts`).
- Хранилище книг `lib/local/book-repository.ts` реализует тот же интерфейс `BookRepository`, что и Supabase-версия, поэтому правила выдачи и повторений (`lib/books/service.ts`) общие. Каталог — из `scripts/data/books-catalog.json` + `official-topics.json`, тексты — `lib/local/book-content.ts` (**новая книга = JSON в `scripts/data/books/` + строка в этом файле**).
- Вход: нет. Страница входа показывает «Продолжить без входа»; `proxy.ts` не трогает Supabase; `(app)/layout.tsx` берёт профиль из cookie. Разделы на базе (предметы, тренажёр, пробник, диагностика, недельный тест, учитель, вступление в класс, админ) перенаправляют на «Сегодня» и скрыты из меню.
- Активность дня (задачи, уроки, повторения книг) пишется в той же cookie: `lib/local/activity.ts` (серия, рекорд, последние 21 день). Страница урока сообщает о сделанном через `POST /api/local/activity` (route handler, а не server action — иначе страница перерисовывалась бы после каждой задачи); запросы идут по очереди, чтобы не затирать cookie. Из активности считаются кольца «Задачи» и «Уроки» (цель 1 урок в день), серия и кружки недели на «Сегодня», огонёк в меню.
- Прогресс самого урока (какие задачи решены, ответы) по-прежнему в `localStorage` (`alemprep:lesson:<id>:v1`). Когда тема закрыта (все задачи решены), урок сам выдаёт книгу (`receiveBookAction`, повторный вызов безопасен) и показывает плашку «Книга теперь у тебя».
- В боевом режиме (Supabase) серия и кружки недели берутся из `profiles` и `attempts` (`getGamification` → `activeDates`); урок пока попыток в базу не пишет — это задача понедельника, кольцо «Уроки» там показывает «скоро».
- В понедельник: убрать `NEXT_PUBLIC_DATA_MODE=local`, применить миграцию 0042 — те же экраны пойдут на Supabase. Данные из браузеров в базу не переносятся (пилот начинается с чистого листа).
- Страница «Прогресс» без базы пока показывает пустое состояние (графики и сетка активности — задача пятницы).

## 7. Правила работы (из `CLAUDE.md`, кратко)

- Перед «готово»: `npm run typecheck`, `npm run lint`, `npm test` зелёные; для маршрутов/сборки — `npm run build`.
- Схема БД — только новыми миграциями (старые не трогать), после изменения обновить `types/db.ts`.
- Тексты — синхронно в `messages/ru.json` и `messages/kk.json` (парность ключей проверяется тестом). Не уверен в казахской фразе — оставь `TODO` и спроси.
- В формулах русские буквы — только внутри `\text{}` (иначе KaTeX ломается; тест уроков это ловит).
- Server Components по умолчанию; `'use client'` только когда нужно состояние; запись в БД — через server actions.
- Секреты (токены, ключи) не писать в чат и не коммитить. `.env.local` не трогать.
- Коммиты — маленькие, по одной задаче; в конце сообщения коммита добавляй строки авторства, которые требует среда.
- Dev-сервер на SWC типы не проверяет — полагайся на `typecheck`.


- Книга показывает «готовится», пока миграция 0042 не применена или текст не написан.

- Общая база с другом: миграция 0042 только добавляет таблицы, но перед применением покажи владельцу и другу, что именно создаётся.
