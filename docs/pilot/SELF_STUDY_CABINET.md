# Самостоятельная подготовка: кабинет и графики

5 октября 2026. Код в `codex/trusted-practice`; этот документ не подтверждает
production deploy или допуск школьников.

## Что можно проверить

- `/ru/teacher` и `/kk/teacher`: активные классы закреплённого учителя;
  координатор видит активные классы своей школы.
- Страница класса: текущие ученики, число серверных принятых попыток, первые
  попытки семейств задач и их баллы, последняя практика, время обновления.
- Отчёт за 30 дней, без истории до текущего вступления в класс/школу.
  Первая попытка считается по истории текущего членства, поэтому старый повтор
  не становится новой первой попыткой после изменения отчётного периода.
- Создание одноразово показываемого кода: 72 часа, до 100 вступлений.
  Это предел приглашения, не измеренная мощность сервера. Код хранится в БД
  только как хеш; передавать его ученикам своего класса.
- `/ru/join-class` и `/kk/join-class`: ученик вводит код, затем самостоятельно
  выбирает темы. Учителю не нужно назначать обязательный урок.
- `/ru/visualization` и `/kk/visualization`: линейная/квадратичная функции,
  коэффициенты a/b, сброс, график и таблица, без платного API и внешней сети.

## Перед production включением

1. Применить **только новую 0036_teacher_self_study_dashboard.sql** в целевом
   Supabase после сверки уже существующих 0029–0034. Она добавляет read-only RPC
   и не меняет таблицы/результаты/старые миграции. Отдельная непринятая 0035
   для назначений ей не требуется; не запускать общий `db push` вслепую.
2. В школе и группе должны существовать активные записи. Учителю нужен active
   `school_memberships.role = teacher` и active `group_teachers` для этой группы.
   Самостоятельно выбрать себе роль из интерфейса нельзя. Для первого пилота
   организатор настраивает школы/классы и привязку реальных учителей.
   Автоматическое создание новых классов/управление учителями ещё не входит
   в этот кабинет; существующий `pilot:provision` настраивает школу/координатора,
   а не всю структуру классов.
3. Для подтверждённых результатов нужен проверенный `LEARNING_V1_ENABLED=true`
   путь самостоятельной практики и принятые immutable versions/publications.
   Импорт/приёмка реального RU/KK контента и production репетиция остаются
   отдельными условиями. Legacy клиентские баллы не переносим в доверенный отчёт.
4. Выпустить проверенный commit и пройти одним ученическим и учительским
   аккаунтом: вход → код → тема → серверный ответ → reload → отчёт.

## Дополнительный Desmos

Локальная визуализация работает и без Desmos. Для внешнего SDK оператор сначала
проверяет условия использования/свой ключ: https://www.desmos.com/my-api.
В Vercel выставить `NEXT_PUBLIC_DESMOS_API_KEY` и `DESMOS_ENABLED=true` только
после этого; `.env.local` и demo keys в репозитории не менялись.

SDK v1.12 загружается лишь после «Открыть Desmos», таймаут 10 секунд,
повтор явный. Закрытие освобождает калькулятор и ResizeObserver. При отказе сети
локальные график/таблица остаются. Не отправляем аккаунт, школу, ответы или
попытки в SDK. Для KK английские элементы SDK обозначены явно; собственные
пояснения/управление/таблица переведены. API docs: https://www.desmos.com/api/v1.12/docs/index.html.
