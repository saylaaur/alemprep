## Проверенный код и ограничения проверки

- Candidate: `cfa2361e1d9ec0ac9ce6440205e34ea78fead2a4`, ветка `codex/l02cr-fixes`, checkout `/private/tmp/alemprep-l02cr-fixes`. Рабочее дерево при проверке чистое. Это локальный candidate, не подтверждённый SHA работающего сайта.

- Свежие `npm run typecheck` и `npm run lint` 25.09 зависли без итогового результата и остановлены исполнителем, exit 143. Build в этом проходе не выполнялся. Вердикт correction остаётся **EVIDENCE MISSING**.

Это свидетельства проблемы чтения зависимостей, но не доказательство отсутствия ошибок типов. Нужна полноценная проверка с локально доступными зависимостями либо чистым CI.

## Приоритет до понедельника

Полный план сохраняется в [execution rebaseline](../superpowers/plans/2026-09-14-execution-rebaseline.md). Условия ограниченного урока — [SUPERVISED_PILOT](SUPERVISED_PILOT.md). Уменьшаем объём первого запуска, не требования к сохранению, доступу и достоверности отчёта.

Предлагаемый первый ученический сценарий: одна школа, 10–15 учеников, один сопровождаемый урок математики, только согласованные темы и принятые KK-задания. Вторая школа — после разбора первого занятия. Это предложение, ещё не подтверждённое школами.

Отложить полный кабинет учителя, Desmos, AI, общий пробник, weekly и расширенные отчёты. Оператор может настроить разрешённую программу и подготовить проверяемую сводку вместо нового интерфейса. Неиспользуемые режимы и legacy-обходы должны быть недоступны на сервере; скрытие ссылок не считается ограничением.

### Пятница, 25 сентября

**Владелец/друг:** сегодня подтвердить время и формат, координатора/учителя, класс и количество учеников, язык и темы, устройства/интернет, допустимые индивидуальные аккаунты. Найти предметного и языкового проверяющего и выяснить, готов ли набор для урока. Сообщить школе, что технический допуск ещё проверяется.

**Техническая работа, по порядку:**

1. Получить работающее окружение проверки: полноценные локальные зависимости вне выгружаемого хранилища либо чистый CI; закрыть L02c gates. Не расходовать время на повторение одинаково зависающих команд.
2. Выполнить L02d по существующей карточке: production submit/review, owner/expiry checks, атомарное сохранение, idempotency и реальные DB-тесты. Не создавать второй scoring-механизм.
3. Подключить минимальную практику (L03a) к start/state/submit/review: public DTO, pending operation, retry/reload, честное подтверждение сохранения. Проверить через браузер и сверить БД.
4. Для сокращённого release оформить конкретный packet ограничений участников/программы/режимов и cutover. Нельзя просто пропустить L03b–d: не перенесённые пути должны быть закрыты, а все экспортируемые actions и прямые REST/RPC проверены. Закрытие прав — отдельной новой миграцией после совместимости приложения, без правки применённых SQL.

Контент и организационные решения идут параллельно технической очереди. Нет принятого KK-набора — ученический сценарий не готов независимо от числа зелёных тестов. Не запускать массовую генерацию/перевод вместо приёмки материала для урока.

### Суббота, 26 сентября: решение за 48 часов до урока

К моменту T−48h из согласованного плана нужны PASS по SP0–SP7 и полная репетиция с учителем на точном release candidate. Если время понедельника неизвестно, нельзя утверждать соблюдение этого окна.

Проверяем: вход/выход на общем устройстве; назначенная KK-практика; отсутствие преждевременных ключей ответов; ответ и объяснение; потерянный HTTP-ответ/повтор/перезагрузка без дубля; запрет чужого ID и обходных записей; сверяемая сводка; школьная сеть; synthetic-нагрузка 15/30 на стенде; восстановление backup, мониторинг, остановка и совместимый откат.

**Если хотя бы один обязательный пункт не подтверждён — согласовать перенос ученической работы.** На понедельник оставить демонстрацию взрослым на synthetic-данных, проверку оборудования/связи и согласование программы. Это полезный старт организационной части пилота, но не состоявшееся занятие учеников на платформе.

### Воскресенье, 27 сентября

При полученном допуске: зафиксировать release, материалы и ответственных; только исправления блокирующих ошибок с повторной проверкой затронутых gates. Новая существенная версия требует новой репетиции и пересмотра допуска.

Без допуска: подготовить демонстрацию, резервный учебный материал с учителем и согласованное сообщение о переносе ученического запуска. Продолжать техническую очередь для следующей даты, не выпускать непроверенный код ночью ради понедельника.

### Понедельник, 28 сентября

- **SP-ready:** одна сопровождаемая группа; оператор наблюдает сохранение и ошибки. Проблема целостности/доступа/критическая ошибка контента — остановка платформенного занятия, резервный материал.
