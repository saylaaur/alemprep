# Карта данных пилота — исходное состояние

Дата: 09.09.2026. Статус: **инвентаризация кода; решение о законном основании, операторе, сроках хранения и размещении ещё не принято**. Документ не заменяет консультацию с профильным специалистом и не разрешает собирать данные детей.

## Что подтверждено в коде

| Категория | Поля/содержание | Где сейчас | Зачем продукту | Кто получает доступ по коду |
| --- | --- | --- | --- | --- |
| Вход | Google OAuth; Supabase Auth создаёт техническую учётную запись и сессионные cookies | Google, Supabase Auth, браузер | Индивидуальный вход и выход | Сам пользователь, Supabase; приложение читает сессию на сервере |
| Профиль | ID, имя/аватар от Google, язык, дневная цель, предмет, дата ЕНТ, целевой балл, XP, стрик, admin-флаг, даты создания/обновления | `profiles` в Supabase | Настройки и личный интерфейс | Ученик — свой профиль по RLS; server role может писать вычисляемые поля |
| Учебная работа | ID ученика, ID задания/сессии, ответ, признак правильности, время, дата | `attempts`, `sessions` в Supabase | Практика, пробник, прогресс, диагностика | Ученик — свои строки по RLS; прямые права пока позволяют менять собственные session/attempt данные, что закрывается блоком 2 |
| Контент | Условия, варианты, правильные ответы, объяснения, таблицы/изображения, язык, публикация, источник | `subjects`, `topics`, `contexts`, `questions` в Supabase | Выдача задания и разбор | Аутентифицированный пользователь читает опубликованный контент; точечная программа пилота ещё не реализована |
| Достижения | ID ученика, ключ бейджа, дата | `user_achievements` в Supabase | Геймификация | Ученик видит своё; правила server-side записи требуют отдельной проверки в блоке 2 |
| AI-история | Вопрос ученика свободным текстом, подсказка, режим, ID задания, дата | `ai_turns` в Supabase | Продолжение диалога по заданию | Ученик читает свою историю по RLS; содержание может быть персональным текстом |
| AI-расходы | Личный дневной счётчик; общий дневной расход запросов и токенов | `ai_usage`, `ai_global_usage` в Supabase | Лимит расходов | Личный счётчик ограничен RLS/RPC; общий счётчик пишет server role |
| Технические данные | HTTP-запросы, ошибки и deployment-метаданные | Vercel/Supabase/GitHub — состав и срок хранения ещё не проверены | Работа сервиса, разбор инцидентов | Команда хостинга/проекта в рамках ролей провайдеров |

В текущем коде нет таблиц школ, классов, групп, назначений, учительских ролей, аудита действий и отчётов. Интеграция файлового хранилища в приложении не обнаружена; наличие ресурсов Storage в живом проекте этим не проверено. План не доказывает реализацию.

## Минимизация и работа с данными

- Для определения масштаба школам достаточно классов, языка, предметов, устройств, одновременного числа учеников и контакта координатора. Не запрашивать ИИН, документы, адреса, медицинские данные или именные списки до выбранного способа входа и согласованной процедуры.
- Для пилота отделить `test/demo` аккаунты от участников серверным признаком. Такой признак должен учитываться в учительской сводке, выгрузках и финансовых отчётах.
- Не помещать в логи токены, cookies, email, полный свободный вопрос AI, ответы детей и полный body задания. Для отладки использовать request ID, тип ошибки и агрегаты.
- Не считать псевдоним или случайный ID анонимизацией: связка с входом и историей занятий остаётся персональными данными.
- Удаление/отзыв участия, экспорт, сроки хранения, оператор, резервные копии и трансграничное размещение выбираются до набора участников. После удаления проверить прекращение доступа к Auth, профилю, попыткам, AI-истории, отчётам и резервной копии по согласованной процедуре.

## Решения, без которых нельзя открыть набор

1. Кто оператор и кто принимает обращения об участии/удалении/экспорте.
2. Где размещаются база, Auth, логи и резервные копии; применимая редакция требований РК и законное основание проверяются профильным специалистом.
3. Способ индивидуального входа на школьных устройствах и порядок восстановления доступа.
4. Сроки хранения каждой категории, включая AI-историю и резервные копии.
5. Кто видит индивидуальный результат, а кто — только агрегат; минимальный размер группы и правила экспорта.
6. Реализовано ли отключение AI для пилота. До формального решения требуется OFF; пока server-side school flag отсутствует, считать это требованием к O01, а не выполненной настройкой.
