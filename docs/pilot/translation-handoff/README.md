# AlemPrep: перевод русского банка на казахский

Актуальное решение владельца, 5 октября 2026: **переводим существующие RU-задачи**.
Не создаём отдельный сайт, не генерируем весь банк заново и не переводим страницу
при каждом заходе ученика. Получаем KK-пары один раз, проверяем, сохраняем в БД.
Кнопка RU/ҚАЗ переключает язык интерфейса и контента.

## Контекст для друга

AlemPrep — подготовка к ЕНТ: математика, физика, информатика. Первый пилот — две
сельские школы Актюбинской области. Ученики **самостоятельно выбирают темы** и
решают задачи; учитель наблюдает активность своего класса. Это не обязательный
урок по одному назначению и не электронный журнал школьных оценок.

На сайте есть RU/KK интерфейс. В текущей ветке добавлены кабинет учителя,
вступление по коду, серверные результаты и отдельные графики функций.
Наличие кода в ветке не означает, что всё это опубликовано на Vercel.

Read-only снимок 05.10: 4 705 вопросов, 4 646 опубликованных RU, 0 опубликованных
KK, 59 черновиков. «Опубликовано» относится к старому банку и **не подтверждает
правильность**. В production новой системе пока 0 RU/KK versions и approved
versions. Поэтому сначала нужен небольшой принятый набор, затем массовое расширение.

## Что тебе отдают

Архив `AlemPrep-RU-KK-translation-2026-10-05.zip` содержит этот README,
`FRIEND_PROMPTS.md`, `REVIEW_TEMPLATE.md`, инструкцию оператора и приватный
`AlemPrep-RU-KK-sources-30-2026-10-05.json`.

В исходном JSON 30 математических задач, один общий контекст, glossary,
условия, варианты, ключи, объяснения, идентификаторы и хеши исходников.
Это техническая выборка, а не подтверждённый пробник или утверждённая программа НЦТ.
У этих 30 источников пока нет immutable версий в production.
Файл не является готовым форматом загрузки в БД.

Тебе **не нужны** Supabase, SQL, service-role key, доступ к Vercel или данные
учеников. Возвращаешь файлы владельцу; интеграцию выполняем мы.

## Первый результат, который нужен завтра

1. Прочитай правила ниже и glossary. Из выборки выбери **5 задач**, начиная
   с простых условий без текста внутри картинок. Не меняй IDs выбранных источников.
2. В Claude отправь контекст из `FRIEND_PROMPTS.md` и эти пять источников.
   Попроси **перевести**, не придумать новые задачи.
3. Сохрани перевод UTF-8 JSON отдельным файлом `kk-candidates-001.json`.
   Сохрани реальные `sourceId`/`sourceHash` и type/difficulty/topic.
4. Проверь структуру и математику: независимо реши RU/KK условие без подсказки,
   затем сравни ключ и объяснение. Ошибку исходника пометь, не маскируй переводом.
5. Проверь казахский язык по смыслу: отрицания, условия, единицы, терминология,
   ограничения переменных. Отдельный чат Claude годится для второго машинного
   мнения; это не человеческая приёмка.
6. Заполни `REVIEW_TEMPLATE.md`: кто реально проверил, что именно, когда,
   какие задачи остаются спорными. Если человека не было — так и написать.
7. Верни владельцу исходники, перевод и review. Мы проверим формат первых пяти.
8. После совместимости формата продолжай до 30; следующая партия — 100–200,
   затем весь выбранный RU-банк. Не ждать перевода всех 4 646 для первого пилота.

При наличии Google drafts твоя работа такая же, только вместо первого
машинного перевода исправляешь пары RU/KK и ручные исключения. На маленькой
партии можно начать с существующей подпиской Claude, не подключая API.

## Что переводится

| Часть | Действие |
| --- | --- |
| Условие `stem`, текстовые `stem_blocks` | Полный смысловой перевод |
| Варианты `options[].content` | Перевод текста, сохранение порядка/IDs |
| Matching `left[].content`, `right[]` | Перевод labels, сохранение связей |
| Объяснение `explanation.blocks` | Все шаги; не сокращать до ответа |
| Контекст `title`, текст/таблицы `content.blocks` | Один перевод на общий контекст |
| Таблицы | Все заголовки/текстовые ячейки, те же размеры/порядок |
| Формулы, числа, знаки, переменные | Не менять; текст внутри формулы — ручной случай |
| Программный код, SQL, HTML как задание | Не переводить syntax, identifiers и литералы без предметной причины |
| Изображения | URL сохранить; текст внутри изображения пометить для обработки |
| UI сообщений/названия тем | Отдельная проверка `messages/kk.json` и названий, не часть вставки вопроса |

Single/multi: сохраняем правильные IDs. **Matching хранит правильный ответ
строкой правой колонки**, поэтому строку в `correct` переводим точно так же,
как соответствующий `right[index]`. Сохраняем индекс/соответствие, а не старый
русский текст ключа. Не переставлять правые элементы и не сливать разные labels.

LaTeX `\\` в JSON экранируется. `$...$`, `$$...$$`, блоки `latex` и десятичные
значения сохраняются. Если в LaTeX есть `\\text{русский текст}`, либо обработать
вручную без изменения математики, либо отметить unresolved. Нельзя оставлять
русский текст в условии и считать задачу полностью переведённой.

## Что не делать

- Не менять тему/сложность/тип, числа, ответы или количество вариантов ради
  «красивого» перевода. Исправление исходного задания — отдельная согласованная ревизия.
- Не выдавать Claude review за проверку учителем/носителем или за валидацию НЦТ.
- Не переименовывать IDs/хеши и не подменять отсутствующий контекст новым текстом.
- Не вставлять старые русские картинки с казахской меткой без замечания.
- Не возвращать один гигантский ответ на весь банк; маленькие файлы проще проверить.
- Не запускать `gen:translate-all`, `gen:insert --publish` или случайный SQL.
  Они не являются безопасным новым pipeline для этих файлов.

## Когда считаем задачу готовой

Есть точная RU→KK пара, согласованный термин, сохранённая математика/структура,
совпавшие ключ и независимое решение, принятое объяснение/контекст/таблица,
реальная запись review. Изменение перевода после проверки требует новой проверки.
Неудачные/спорные задачи откладываем и расширяем банк принятыми партиями.

Машинные черновики сами по себе не публикуются. Оператор повторно сверяет hash
источника, создаёт KK-контексты, связывает RU/KK family и загружает версии как draft.
Публикуется только точная принятая версия. Подробности: `OPERATOR_GUIDE.md`.
