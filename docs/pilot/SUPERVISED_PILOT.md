# Первый сопровождаемый пилот — условия и допуск

Версия 1 · 10 сентября 2026. Пользователь согласовал направление ограниченного пилота в обсуждении. Школы ещё не подтвердили дату/размер групп. Этот документ уточняет первую апробацию; [полный технический план](../production/README.md) и [стратегия](../../ROADMAP.md) сохраняются. Никакой пункт ниже не выполнен самим написанием документа.

## Предложенный объём

- Цель первого занятия — 20–21 сентября 2026, после контрольной репетиции. Это ориентир, не обещание и не согласованная дата.
- Две школы последовательно. Сначала одна группа 10–15 учеников в первой школе, разбор и исправления, затем вторая. Одновременное подключение двух школ не предполагается без новой приёмки нагрузки.
- Один предмет: математика, 2–3 темы по согласованию учителя, 30–50 предметно и языково принятых пар RU/KK. Казахский проверяется первым. Формулы, варианты, объяснения, таблицы и контексты входят в приёмку.
- Один основной сценарий: индивидуальный вход → выбранная практика → подтверждение сохранения → объяснение → сводка занятия. Цель первой апробации — доступность, понятность, сохранение и обратная связь. Рост результатов ЕНТ не обещается.
- Учитель и технический оператор присутствуют на занятии. Есть заранее подготовленный резервный материал и согласованный канал поддержки.
- AI, Desmos, общий пробник, weekly и дополнительные режимы отключены для пилотных аккаунтов **на сервере**. Скрытой кнопки недостаточно. Сейчас этот переключатель ещё не считается реализованным.

## Чем отличается от самостоятельного школьного продукта

На этом этапе учитель может выбрать программу вместе с оператором, а оператор выдать контролируемый доступ и подготовить сводку вручную из проверенных данных. Это временная замена интерфейса назначения/отчёта, не замена достоверности записей и прав доступа.

Учителю не выдаётся глобальный admin/service_role. Школе доступна только своя допустимая сводка через согласованный канал, без данных другой школы; внешнему отчёту достаточно агрегатов. Передача отчёта не авторизуется автоматически этим документом. Период, cohort/program version, правила подсчёта и версия запроса фиксируются, числа сверяются с исходными подтверждёнными результатами. Таблица, заполненная на глаз, не является отчётом системы.

Полные S01–S04/R01–R03 и UI-критерий G4 остаются обязательными перед самостоятельной работой учителя/расширением. Первый сопровождаемый release получает отдельный verdict **SP-ready**, а не P01/G0–G7 complete. Он не даёт разрешения открывать продукт всем школьникам.

## Обязательные доказательства перед участием детей

| Gate | Что должно быть реализовано и проверено | Связь с полным планом |
| --- | --- | --- |
| SP0 Условия | Координатор, допустимые аккаунты, участие/доступы, размещение app/DB/Auth/logs/backups, правила хранения/отзыва и ответственные согласованы; бюджет принят | D02–D06; релевантные D01/G0. Synthetic репетиция может идти до этих решений |
| SP1 Release | Точный commit/schema/env, зелёные CI и реальный DB/browser smoke, изолированный test target | E01/E02/E03; deployment evidence |
| SP2 Целостность | Сервер определяет actor/выдачу/ответ; клиент не получает ключ ответа до допустимого раскрытия; атомарно сохраняются попытка, результат и аудит; повтор не даёт дублей; прямой REST/RPC не подделывает свой результат | L01–L04 обязательные инварианты и реальные тесты, без исключения из-за размера группы |
| SP3 Доступ | На сервере и уровне данных ограничены участники, программа/версии и режимы; собственные результаты изолированы; смена URL, прямой API и чужой ID не обходят ограничения; отозванный участник теряет доступ | L04, scope/flags по S/O. Программа allowlist не может существовать только в UI |
| SP4 Контент | Все выданные задания и объяснения приняты человеком в обеих локалях, исходники/версии/проверки зафиксированы; нет пустой назначенной темы или скрытого RU fallback | C00c и version/publication инварианты L01/C01 |
| SP5 Отчёт | Учитель получает разрешённую сводку своего занятия; counts сходятся с подтверждёнными записями, версия/период/знаменатель воспроизводимы | R-инварианты; ручное формирование разрешено, ручное выдумывание результатов — нет |
| SP6 Надёжность | Auth/logout на общих устройствах; timeout/retry/reload без потери/дубля подтверждённого ответа; 15/30 одновременных synthetic участников на согласованном стенде; реальные школьные устройства/сеть | U/O; 15/30 — тестовая цель для данного ограниченного режима, заменяется при согласовании N |
| SP7 Эксплуатация | Резервная копия реально восстановлена на изолированном стенде; согласованы допустимая потеря/срок восстановления; есть error monitoring, расходные лимиты, остановка занятия, rollback и ответственный | O01–O04; наличие backup-кнопки не равно restore evidence |

Для каждого gate в `docs/pilot/RELEASE.md` исполнитель добавляет: status PASS/FAIL/NOT CHECKED, evidence, SHA/окружение, дату, ответственного и ограничения. На 10 сентября эта таблица — **требования, не результаты**. В тестах не использовать реальные детские данные; не проверять атаки на production аккаунтах учеников.

Ранний scope требует оформить конкретный implementation packet и тесты для отсутствующих participant/program restrictions и ручной сводки до изменения кода. Не писать «часть L выполнена» без списка инвариантов и evidence. Общие E/L/C задачи переиспользуются; отдельную конкурирующую систему scoring ради даты не создавать. Технический reviewer оценивает packet и точный candidate, владелец принимает допуск вместе со школьным ответственным.

## Контроль срока и остановка

13 сентября — оценка готовности: есть ли данные от школ, проверяющий, тестовый контур и доказуемый путь закрытия SP0–SP7. Любой нерешённый критический риск может сдвинуть занятие за пределы 20–21 сентября. Сопровождение не исправляет уязвимую БД.

За 48 часов до занятия — полная репетиция на candidate с учителем. Без PASS по всем SP-gates детям доступ не открываем; проводим демонстрацию со взрослыми на synthetic данных. При проблеме сохранения, доступа к чужим данным или критической ошибке задания занятие останавливаем, переход на резервный материал не объявляется успешной работой платформы.

После первого занятия: журнал инцидентов, фактическое число участников, активация/завершение, затраченное время учителя, 3 главных неудобства и решение о второй школе. Повторные занятия без технического сопровождения допускаются только после полного школьного release gate. В публичном описании называем этап «ограниченная сопровождаемая апробация», а результаты — фактическими числами.
