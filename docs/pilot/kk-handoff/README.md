# AlemPrep: задание другу по казахскому контенту

**05.10: этот пакет — исторический план генерации native-KK. Новое решение:
перевод существующего RU-банка. Использовать [актуальный handoff](../translation-handoff/README.md)
и его промпты/формат; не смешивать два договора импорта.**

Дата: 2 октября 2026. Цель первого занятия: понедельник, 5 октября. Это рабочий срок, не подтверждение готовности платформы.

## 1. Что мы делаем и зачем

AlemPrep — платформа подготовки к ЕНТ для Казахстана. Есть русский и казахский интерфейс, практика, формулы, объяснения и сохранение результатов. Готовим пилот в двух сельских школах Актюбинской области; первый запуск ограничиваем одной группой и одним сопровождаемым уроком. Число учеников, время и темы ещё должен подтвердить школьный ответственный.

Проблема: казахского интерфейса недостаточно — нужен проверенный казахский банк. У школы должна быть возможность пройти целый урок на казахском, включая условие, варианты, объяснение и обратную связь. Пустые темы и русская подстановка не подходят.

Мы раньше обсуждали покупку десяти казахских пробников и генерацию вариантов. Итог плана 20 сентября: сначала маленькая партия и проверка, затем масштабирование. Десять пробников не являются обязательным входом. Массовый перевод всего русского банка сейчас не нужен. Google-перевод оставлен как запасной инструмент для отдельных тем.

**Твоя зона:** подготовить новые казахские задания и проверяемый пакет файлов. **Наша зона:** проверить пакет, написать/подключить импорт, создать версии в БД и программу урока, проверить выдачу, отчёты и доступ. Тебе не нужны Supabase, SQL, GitHub-доступ, API-ключи или данные учеников.

## 2. Конкретный результат

Сначала отправь **5 кандидатов**, чтобы мы проверили формат. Затем доведи до **30 кандидатов**, из которых выберем 10–15 принятых задач на первый урок и резерв. Не обещаем, что все 30 будут опубликованы.

Рабочее предположение до ответа школы: профильная математика, старшие классы, тема линейных и квадратных уравнений. Это не полный пробник и не утверждённая программа НЦТ. Реальная согласованная тема школы имеет приоритет.

| Параметр | Значение |
| --- | --- |
| subject | `math` |
| locale | `kk` |
| topic_slug | `linear-quadratic-rational-equations` |
| type | `single` |
| Ответы | 4 варианта, IDs `A`, `B`, `C`, `D`; ровно один правильный |
| difficulty | 2 — базовые; 3 — средние; это внутренняя оценка |
| Состав 30 кандидатов | 15 линейных + 15 квадратных; около 20 базовых и 10 средних |
| Формат | UTF-8 JSON, объяснение блоками, формулы LaTeX |

Первые пять: три линейных и два квадратных. Разнообразие навыков: раскрытие скобок, дробные коэффициенты, перенос слагаемых; факторизация, дискриминант, сумма/произведение корней. Не выдавай 15 замен чисел в одной формуле за 15 разных навыков. Если нужны дробно-рациональные уравнения, сначала согласуем их и ОДЗ; в первую партию они не обязательны.

Не брать геометрию с рисунками, сложные контексты, multiple choice с несколькими ответами и matching в первый пакет. Это ограничение первого урока, а не всей платформы. Если школа выберет другую тему — сообщи до массовой генерации, не придумывай новый slug.

## 3. Как работать с Claude

1. Создай отдельный чат/проект для этой работы. Прикрепи README, PROMPTS, `batch.schema.json` и `example-batch.json` из этого пакета. Наш Git-репозиторий не обязателен.
2. Работай через свою оплаченную подписку в интерфейсе Claude. Не подключай API и не включай платное расширение лимита ради этой партии без отдельного решения. Подписка и Console/API оплачиваются отдельно: [официальное объяснение](https://support.claude.com/en/articles/9876003-i-have-a-paid-claude-subscription-pro-max-team-or-enterprise-plans-why-do-i-have-to-pay-separately-to-use-the-claude-api-and-console).
3. Вставь стартовый промпт из PROMPTS. Получи пять задач файлом `batch.json`. Если Claude выдаёт кодовый блок, сохрани только JSON без тройных кавычек.
4. Сделай вторую проверку в новом чате: передай только ID, условия, таблицы и варианты, **без `correct` и объяснений**. Попроси решить заново и проверить все ответы. Затем сравни с первым ключом. Это снижает привязку к готовому ответу, но остаётся проверкой модели.
5. Прочитай каждое казахское условие вслух: понятно ли, что ищем, нет ли двусмысленности и русских оборотов. Независимо проверь математику сам либо попроси человека, способного это сделать. Не надо искать формальную должность для галочки; нужен реальный проверяющий, который понимает решение и казахский язык.
6. Отправь нам первые пять и замечания. Пока мы проверяем формат, можно готовить следующие партии по пять, сохраняя тот же контракт. Не жди готовности сервера для работы над содержанием.
7. В конце объедини кандидатов, сохрани замечания по каждому ID и отдельный список рекомендованных 10–15 задач для урока.

Учитель школы выбирает соответствие своему классу. Если человека для проверки пока нет, честно сдай **черновик с pending-review**: он полезен для нашей интеграции, но модель не может поставить подпись человека. Не отмечай задачи approved и не заявляй их официальными заданиями НЦТ.

## 4. НЦТ, пробники и скриншоты

Самый независимый от закупки маршрут сейчас — собственные условия по выбранным математическим навыкам, созданные с помощью Claude. Для них `origin = authored`: это означает новый материал, в том числе AI-assisted, а не утверждение о ручном авторстве или гарантированной уникальности.

Если есть разрешённый к использованию источник, можешь использовать оригинал/вариант с честно указанным происхождением. Условия доступа и использования фиксируем отдельно. Покупку файла не записывай автоматически как подтверждение права размещения на нашем сайте. Если условия неизвестны, не копируй его текст в публикуемую партию: составь собственную задачу по общей учебной теме, без пересказа конкретного исходника.

Для чтения разрешённых материалов PDF удобнее отдельных скриншотов. Если есть только скриншоты: одно полное задание на изображение, все варианты, весь рисунок/таблица, видимые степени и дроби; имя `source01-page03-q07.png`. Сохрани оригинал. Нечитаемый знак, обрезанную таблицу или рисунок нельзя угадывать. Claude сначала транскрибирует; человек сверяет с картинкой; только затем возможна переработка.

Не выгружай исходные платные PDF/скриншоты в публичный Git. Передавай приватно, только если это допускается условиями источника. Не присылай аккаунты, пароли, cookies, ключи и сведения об учениках.

## 5. Формат и обязательные детали

`batch.schema.json` описывает **формат передачи**, а не уже существующий импортёр. Импортёр native-KK ещё предстоит подключить у нас. `body` и `explanation` соответствуют структуре задач проекта; поля происхождения будут обработаны адаптером. Не запускать старые `gen:all` / `gen:insert --publish`: они не являются этим маршрутом.

Файл `example-batch.json` — два синтетических примера формата, **не принятый учебный контент**. Не включай их автоматически в свою партию.

- `id`: стабильный локальный ID, например `kk-eq-001`; при исправлении сохраняй ID, повышай `revision`.
- `family_key`: один ключ для близких параметрических вариантов; не меняй его ради дополнительных наград. Для независимо составленных задач — отдельные ключи. Окончательное сопоставление семейств делает наша интеграция.
- `skill`: короткое название проверяемого навыка для редактора.
- `body.stem`: всё условие. Если есть `stem_blocks`, рендер может использовать их вместо stem: повтори в текстовом блоке полное условие и добавь таблицу, чтобы ничего не исчезло.
- `options`: 4 разных по смыслу ответа с IDs A/B/C/D. Корень и множество корней формулируй точно: «все корни» и «больший корень» — разные вопросы.
- `correct`: ID одного варианта, не текст и не индекс.
- `explanation.blocks`: обычно 3–6 содержательных шагов на казахском. Объясни преобразования и проверку, а не только «верный ответ B». В конце ответ должен совпадать с `correct`.
- Формулы в строках — `$...$`. В JSON обратную косую черту экранируй: `"$\\frac{1}{2}$"`. Не вставляй HTML, исполняемый код, Markdown-таблицы, ссылки на случайные картинки.
- Таблица: блок `{"type":"table","columns":["x","y"],"rows":[["1","2"],["2","4"]]}`. Каждая строка имеет столько же ячеек, сколько заголовков. Если таблица нужна для решения, она обязательна.
- В первой партии нет внешних изображений/контекстов; если задача от них зависит, замени её самостоятельной текстовой или отложи с причиной.
- `provenance`: точное происхождение, реальная ссылка/номер при наличии, `parent_id` для варианта. Для собственного задания source/ref/parent равны null; rationale — какой навык, откуда условие. Не выдумывать ссылки, номера страниц, лицензию и источник.
- `issues`: реальные нерешённые сомнения. Пустой список означает отсутствие заявленных сомнений модели, **не подтверждённую проверку**.

## 6. Проверка каждой задачи

- [ ] Условие решаемо без отсутствующих данных, картинки или русского исходника.
- [ ] Независимо получен ответ; проверены ОДЗ/знаки/дроби/корни, если они есть.
- [ ] Только один вариант правильный; нет одинаковых значений под разной записью.
- [ ] `correct`, вывод объяснения и подстановка согласуются.
- [ ] Для квадратного уравнения проверено, спрашивается один корень, оба корня или другая величина; нет потери второго корня.
- [ ] Казахский читается естественно и однозначно; сомнительные термины отмечены для человека.
- [ ] Формулы и таблицы полные. После изменения ключа/условия повторены обе проверки.
- [ ] Близкие варианты помечены общим family_key, похожие условия не замаскированы новыми ID.
- [ ] Происхождение записано честно. Ни один машинный ответ не обозначен human-approved.

Одна серьёзная математическая ошибка в партии — повод перепроверить задачи того же семейства/шаблона, а не только заменить один ответ.

## 7. Что прислать обратно

Создай папку `kk-math-delivery`:

1. `batch.json` — все кандидаты по приложенной схеме.
2. `solutions-independent.md` — отдельное решение каждого ID без опоры на первый ключ; указать, кем сделано: модель/человек.
3. `review.md` — по форме REVIEW-TEMPLATE: кто и что реально проверил, ID/revision, найденные ошибки, pending/accepted-for-import-review/rejected. Человек заполняет подпись сам.
4. `lesson.md` — упорядоченные 10–15 рекомендуемых ID и 5 запасных, цель урока, оценка времени, причины отбора. Допускается отметить, что человеческая проверка пока не завершена.
5. `sources.md` — происхождение партии; для собственной генерации прямо написать это. Для сторонних материалов — источник/локатор/имеющееся подтверждение условий, без выдуманных прав.

Если можешь — zip этой папки; иначе просто пять файлов. Формат важнее красивого PDF. После отправки не меняй файлы молча: пришли новую revision. Мы вычислим content hash и привяжем окончательную приёмку к точным байтам/каноническому содержимому; если файл меняется после проверки, проверка затронутых задач повторяется.

Наша следующая работа: структурная проверка → независимая сверка решений → человеческая языковая/предметная приёмка → dry-run → импорт immutable draft versions → публикация только принятого списка → фиксированная KK-программа → проверка урока и отчёта. Присланный JSON не попадёт в production автоматически.
