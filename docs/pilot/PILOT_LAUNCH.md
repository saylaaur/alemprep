# AlemPrep: запуск ограниченного школьного пилота

Обновлено 15.10.2026. Это текущая операционная инструкция. Сентябрьские планы и отчёт 11.10 — история; выполненные hosted шаги из них не повторять.

## Формат и границы

Подтверждена первая школа: четыре 11-х класса, 102 заявленных участника. Организатор уточнил, что **все четыре класса работают на казахском**. Вторую школу подключать после первого стабильного прогона. Ученики готовятся самостоятельно по математике, учитель наблюдает результаты своего класса. Первый запуск — 10–20 человек; затем расширение по классам. Это ограничение организации запуска, не измеренная мощность production.

Доступны четыре темы: прогрессии — 39 заданий, уравнения — 28, степени — 11, корни и выражения — 11. Всего **89 семейств на каждом языке**; RU/KK — языковые версии одного банка, не 178 разных задач. Контент выпущен по разрешению владельца после Claude AI + Codex AI review; человеческая языковая приёмка не заявляется. Полный банк ЕНТ, пробники, диагностика и weekly не входят в этот пилот. Сохраняются `LEARNING_V1_ENABLED=true` и `PILOT_TOPICS_ONLY=true`.

Пилот предлагается на 14 дней от первого реального старта класса. Его срок, время, устройства, интернет и ответственного на время первого входа согласует организатор. Данные настоящей школы/классов/аккаунтов хранятся приватно, вне Git.

## День 0: первый реальный ученик

1. Технический ответственный и учитель договариваются о времени и остаются на связи. Открыть сайт на настоящем устройстве и школьном интернете.
2. Учитель входит подтверждённым Google-аккаунтом на `https://alemprep.vercel.app/kk/teacher`, выбирает свой класс и создаёт отдельное приглашение. Остальным классам нужны свои ссылки. Не создавать общий код на 102 участников.
3. Ссылку сначала получает один ученик. Он входит собственным Google, вступает в класс и только после этого начинает практику. Данные до вступления в учительский отчёт не включаются. Пароли и именные списки детей организатор не собирает.
4. Ученик выбирает математику и доступную тему, отвечает, ждёт подтверждения сохранения и обновляет страницу. Ответ остаётся сохранённым, обновление не создаёт вторую попытку. При необходимости проверить формулу, таблицу и график на телефоне.
5. Учитель обновляет отчёт: ученик появился, есть ровно одна новая подтверждённая попытка. CSV показывает те же числа. Отдельная повторная отправка не повышает балл первой попытки семейства.
6. Зафиксировать время и результат приватно. После успеха подключить 10–20 учеников, затем остальные классы. Сбой не маскировать локальным синтетическим PASS.

Командная репетиция RU/KK уже пройдена; первый школьный сценарий проверяет другое устройство и сеть. Это следующий шаг фактического запуска, а не повод начинать новый блок разработки или массовый перевод перед первым учеником.

## Язык и ссылки

`school_groups.locale=kk` и языковые настройки профиля не переписывают уже открытую вкладку `/ru/`. Интерфейс и выдача следуют URL. Учителя используют `/kk/teacher`, ученики — ссылки с `/kk/`. Если ранее передали ссылку с `/ru/`, заменить только языковой префикс, сохранив код, либо сформировать новое приглашение из KK кабинета. Уже вступившему ученику повторное вступление не требуется.

Текущий `ClassInvite` формирует языковой префикс по открытой локали. Секретный код передавать только своему классу; он действует до 72 часов и допускает до 100 вступлений. Это ограничение одного приглашения, не общей мощности платформы.

## Доступ, инфраструктура и восстановление

- Hosted 0041 уже применена. **Не применять 0001–0041 заново, не выполнять production reset.** Не изменять immutable версии и не пересчитывать принятую историю молча.
- В Supabase проверены точные production/preview callbacks без wildcard, production Site URL, `token_refresh=1800`. Google Audience именно рабочего OAuth-клиента нельзя объявлять проверенным по случайно открытому одноимённому Cloud-проекту. Реальные teacher-входы подтверждены; вход первого школьного pupil проверять на месте.
- Учителю не выдавать service-role, SQL Editor или глобальный admin. Скачивание CSV каждый раз проходит свежую проверку scope и отдаёт private/no-store.
- Свежая копия хранится вне Git с правами каталога 0700 и файлов 0600. Public, auth, storage schema и данные сохранены; Storage objects на снимке 0. Истории `supabase_migrations.schema_migrations` в исходной hosted БД нет: миграции применялись вручную.
- Проверка восстановления прошла в локальном Supabase Postgres 17, network=none, без опубликованных портов; контейнер остановлен. Данные совпали во всех 68 таблицах до и после rollback функциональной пробы. Схемы свежего dump побайтово совпали с ранее восстановленными схемами, поэтому данные обновлялись только в закрытой локальной копии.
- SQL restore не восстанавливает Vercel/Google настройки, облачные секреты или Storage-файлы. На работающий hosted проект restore/TRUNCATE не направлять. Операторские команды, ключи, Auth dump и exports не коммитить и не пересылать школе.
- Оператор сохраняет свежий снимок перед расширением и в дни занятий, проверяет хеши и доступность копий. Автоматическое расписание, облачная offsite-копия, гарантированный RPO/SLA не заявляются. Старые копии не удалять автоматически в ходе пилота.

## Наблюдение и отчёт

В день первого прогона проверить сайт/БД, после — подтверждённые ответы и CSV. Ежедневно фиксировать только нужные школьные агрегаты: вступившие, участники хотя бы с одной подтверждённой попыткой, число попыток, баллы/знаменатель первых семейств, ошибки сохранения, языковые и математические замечания. В конце первой недели проверить возвращаемость; к концу второй — обсудить с учителями продолжение и темы для следующей партии контента.

CSV — текущий снимок за 30 дней после вступления с report ID, asOfUTC, Asia/Almaty и `teacher-self-study-v1`. Это не произвольный 14-дневный фильтр и не доказательство роста балла ЕНТ. Сохранять исходные snapshots приватно; новую выгрузку не выдавать за прежний snapshot. Для управления образования готовить согласованные агрегаты без имён/UUID/ответов. Отправка отчёта — отдельно по поручению организатора.

## Если что-то пошло не так

- Ошибка входа: записать точный экран/время и фактический выбранный Google-аккаунт приватно; не отключать Auth ради демонстрации.
- Ошибка сохранения/БД: остановить новые ответы, сохранить pending для своего аккаунта и повторить после восстановления; офлайн-сдача не обещана.
- Чужие данные, подмена баллов, массовые дубли: остановить набор и занятия, сохранить evidence и ограничить затронутый доступ штатным механизмом.
- Ошибка условия/перевода: карантин exact версии с аудитом; исправление новой версией, предыдущая история сохраняется.
- Сбой графика: задача остаётся доступной; график вспомогательный. Графики не требуют платного API.
- После ошибочного деплоя: Vercel rollback только на совместимый проверенный deployment, затем одна репетиция. Не выключать trusted режим, не возвращать клиентские grants и не откатывать схему вниз.

## Следующий приоритет

Запуск первого школьника → первая группа → исправления по реальным обращениям → расширение банка проверенными партиями → вторая школа. Полный ЕНТ, новые предметы, сложный LMS и крупные зависимости не блокируют этот ограниченный запуск. Известный долг зависимостей остаётся в отчёте 11.10; audit-clean не заявляется.
