# AlemPrep: действующий план запуска пилота

09.10.2026. Это текущая спецификация и операционная инструкция ограниченного самостоятельного пилота. Старые сентябрьские и ранние октябрьские планы сохраняются как история. Владелец поручил агенту подготовку и выпуск без ожидания промежуточных согласований.

## Формат

Две сельские школы Актюбинской области, самостоятельная математика по темам на RU/KK, учитель наблюдает свой класс. Первый прогон — 10–20 учеников и человек на связи; затем расширение. Предлагаемая длительность — 14 дней от реального первого входа класса. Даты и число участников школа ещё не подтвердила. Это ограниченный набор тем, а не полный банк ЕНТ.

Пробник, диагностика и weekly скрыты. Обязательные назначения не нужны. Встроенный графический инструмент и графики подходящих задач работают без платного API; Desmos дополнительный. На сайте не вызывается перевод при каждом открытии задания.

## Команда проверки

В отдельном worktree, с существующим приватным env-файлом:

```bash
npm run pilot:check -- --project-ref=euypaocjzcqlapfilrak --env-file=/Users/macbook/Desktop/alemprep/.env.local --require-bindings
```

Она выполняет только чтение approved snapshots и счётчиков подключений. Вывод — агрегированный JSON без имён, email, ключей ответов и токенов. Legacy published count не используется. Exit0 означает только проверки этой команды; реальное занятие она не сертифицирует. Exit2 — найденный content blocker или отсутствующие требуемые bindings; exit1 — ошибка доступа/формата/целевого проекта. Наличие отдельных bindings не доказывает корректность всех связей и заменяется настоящей репетицией.

Сейчас checker правдиво выдаёт `contentReady=false`: один excluded source ещё approved. После применения карантина ожидаем RU89/KK89, без `excluded-source-approved`. `school-bindings-missing` исчезнет только после настоящего подключения.

## Точный карантин одной RU задачи

[quarantine-ambiguous-ru.sql](quarantine-ambiguous-ru.sql) — транзакция данных, не новая schema migration. Условия и immutable версия не переписываются, прошлые ответы сохраняются. Она снимает ровно одну approved RU версию по UUID и exact hash из выдачи и пишет один audit event; повтор безопасен. Ошибка аудита откатывает publication — проверено локальным тестом.

Причина: источник32683e42 имеет перечисление членов через запятые вместо явно записанной суммы. KK версия не принята; сохранение спорной RU записи не нужно для пилота. Backup точного snapshot/publication и SHA256 находится вне Git: `/Users/macbook/alemprep-private/pilot-20261009/`. До этого прохода source не менялся. Hosted SQL **не выполнен**: недоступна owner-консоль. При доступе выполнить файл целиком в SQL Editor проектаeuypaocjzcqlapfilrak, затем повторить `pilot:check`. Не запускать 0001–0040 заново и не выполнять production reset.

## Что требуется от организатора

Одна приватная карточка на класс: настоящее название школы, класс, язык ru/kk, число участников первого прогона, email вошедшего Google-учителя, email вошедшего координатора, день/время и ответственный контакт на время запуска. Заранее собирать именные списки детей не нужно: они вступают самостоятельно. Организатор подтверждает порядок участия и обработки данных со школой.

Использовать [START_FIRST_CLASS.md](START_FIRST_CLASS.md) и приватно заполненный bootstrap SQL. Учителям не выдаются service-role, SQL Editor или глобальный is_admin. Email/заполненные SQL/CSV не попадают в Git. Не создаём фиктивные hosted школы ради галочки.

## Репетиция перед первой группой

1. Проверить exact deployment и оба флага true на Production, серверный service-role есть. На публичном домене сохраняется точный Google callback.
2. Ученик с аккаунтом вне разработчиков проходит Google-вход. Проверить Google Audience: Testing может ограничивать школьные аккаунты. Не отключать защиты и не создавать обход входа ради демонстрации.
3. Учитель видит свой класс и создаёт ссылку приглашения. Другой учитель не видит этот класс.
4. Один настоящий ученик открывает ссылку, выбирает собственный аккаунт, вступает и решает одну задачу в согласованной локали.
5. Reload сохраняет ответ и балл. Повтор сохранения после обрыва сети не создаёт второго результата.
6. Учитель обновляет отчёт: ровно+1 попытка нужного ученика. CSV имеет тот же результат. Повторную задачу считать попыткой, не новой family; первую неверную попытку не исправлять баллом последующего повтора.
7. На настоящем телефоне проверить формулы, таблицы, график подходящей задачи, RU/KK переключение и слабую связь. В общем кабинете — выход, вход другим учеником, отсутствие старого черновика.
8. Зафиксировать время и PASS/FAIL каждого шага приватно. Нельзя назвать этот путь пройденным по локальной синтетической проверке.

## Короткая инструкция ученику

Открой ссылку класса → войди через собственный Google → «Вступить» → выбери язык → «Предметы → Математика» → доступная тема → ответ → «Проверить». Прочитай объяснение, при наличии открой график, затем «Следующая задача». После сохранения результат должен оставаться при обновлении страницы. Если связь пропала, дождись статуса и повтори сохранение кнопкой; не создавай новый ответ с новым аккаунтом. По спорной задаче запиши тему и условие/скрин без чужих данных и передай учителю. На общем устройстве нажми «Выйти».

## Короткая инструкция учителю

Войди тем email, который привязан организатором. «Кабинет учителя → класс → Создать новый код → Скопировать ссылку». Ссылка передаётся только своему классу; код действует72часа, до100 вступлений — это лимит приглашения, не мощность сервера. Проверь первого ученика, затем подключай небольшую группу. Отчёт показывает подтверждённую практику за30дней после вступления, баллы первых попыток семейства и повторы отдельно. Пустой балл означает отсутствие оцениваемых первых попыток. «Скачать отчёт (CSV)» содержит имена; хранить и передавать только уполномоченным сотрудникам школы. Для управления образования подготовить агрегат без имён/UUID/ответов.

## Предлагаемый 14-дневный пилот

| День | Работа | Проверка |
| --- | --- | --- |
| 0 | Одна реальная репетиция, backup/restore, связь и поддержка | Вход/ответ/reload/teacher+1 PASS |
| 1–2 | Первая группа10–20, по10–15 задач выбранной темы, короткий feedback | Сохранение подтверждено, нет дублей/чужих данных |
| 3–7 | Самостоятельная практика, после стабильности вторая школа/локаль | Возврат пользователей, обращения, счётчики |
| 8–13 | Продолжение, разбор языковых/математических ошибок | Исправления новой версией, история сохранена |
| 14 | Snapshot отчёта, короткий разговор с учителями | Решение о продолжении и расширении |

Длительность и объём — предложение, не обещанные школам условия. Начать с четырёх имеющихся тем; добавление всего банка/предметов не блокирует этот пилот.

## Метрики и отчёт

Активный участник — хотя бы одна подтверждённая попытка, а не вход. Отдельно записать включено/активно, общее число принятых попыток, first-family numerator/denominator, ошибки сохранения, языковые/контентные замечания и возвращение на следующей неделе. В CSV фиксированы snapshot ID, asOfUTC, период30дней, Asia/Almaty и `teacher-self-study-v1`. Сохранять исходный CSV приватно: новая выгрузка имеет новый ID и может содержать поздние ответы. Это текущий30-дневный dashboard snapshot, не произвольный14-дневный фильтр и не доказательство роста балла ЕНТ.

Для отчёта управления: период самого пилота, школы/число групп, размеры знаменателей и согласованные агрегаты; не выгружать имена/ответы. Для группы меньше10 предложен объединённый агрегат двух школ; подтверждение формы/адресата у организатора. Экспорт никому автоматически не отправляется.

## Поддержка и остановка

В день первого прогона технический владелец должен быть на связи; конкретные часы/контакт согласует организатор. Перед началом проверить сайт/провайдеры, после — подтверждённые ответы и CSV. При ошибке записать UTC/местное время, URL без токенов и код/request ID; не публиковать ключи, cookies, ответы и имена в GitHub.

- Отдельный сбой графика/Desmos: продолжать задачу, график вспомогательный.
- Сбой БД/сохранения: остановить новые задания, сохранить owner-bound pending и повторить после восстановления; не обещать офлайн-сдачу.
- Чужие данные, подмена баллов или массовые дубли: остановить набор и занятия, сохранить приватное evidence, ограничить затронутый доступ через штатный механизм и исправить причину.
- Ошибка условия: карантин exact версии и журнал; новая редакция/приёмка отдельно, прежние факты не пересчитываются молча.
- Новый интерфейс сломан: Vercel rollback на совместимый `c5b535a` с теми же схемой0040, service-role и trusted/pilot flags. Проверить alias→SHA и одну репетицию. Не выключать trusted режим, не возвращать клиентские grants и не откатывать БД вниз.

## Backup и восстановление

Снимки контента/receipt из переводных пакетов и приватный backup одной версии существуют. Это **не** backup Auth и результатов детей. Полная hosted выгрузка и её восстановление здесь пока не выполнены.

У владельца настроить официальный CLI login/link через нормальную авторизацию. Перед выгрузкой сверить linked project euypaocjzcqlapfilrak; каталог вне Git с `umask 077`. Команды для этого linked проекта:

```bash
npx supabase db dump --linked --role-only --file /Users/macbook/alemprep-private/pilot-backup/roles.sql
npx supabase db dump --linked --file /Users/macbook/alemprep-private/pilot-backup/schema.sql
npx supabase db dump --linked --data-only --use-copy --file /Users/macbook/alemprep-private/pilot-backup/data.sql
```

Перед этим каталог должен существовать. Это логическая выгрузка: стандартный schema dump исключает managed схемы. До восстановления отдельно сверить данные auth.users/auth.identities, нашу связку trigger handle_new_user и history supabase_migrations; необходимые изменения auth/storage восстановить по собственным миграциям или официальной инструкции. Файлы Storage выгружаются отдельно от записей БД. При Vault/шифровании требуется отдельный перенос ключей по официальному руководству. Не считать наличие трёх файлов успешным восстановлением. Не передавать пароль через публичный чат или URL команды. Проверить состав дампа (Auth/необходимые managed данные и Storage объекты отдельно), хеши и доступ к резервной копии. Восстановление — только в отдельный закрытый тестовый проект/локальную БД с network/email/AI отключёнными, не в работающий production. Сверить content/version hashes, school scope, число фактов/receipts, один replay и teacher report; восстановленные данные учеников не использовать для показов. Частоту/retention и ответственного подтвердить до допуска, без выдуманного SLA/RPO.

Сверено09.10 с [Supabase backups](https://supabase.com/docs/guides/platform/backups) и [CLI db dump](https://supabase.com/docs/reference/cli/supabase-db-dump) и [backup/restore](https://supabase.com/docs/guides/platform/migrating-within-supabase/backup-restore): тариф/доступ к backup проверить в консоли; наличие приложения на Vercel не означает резервирование БД. Платные планы агент не покупал.
