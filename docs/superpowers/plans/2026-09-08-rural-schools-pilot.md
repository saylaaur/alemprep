# Пилот AlemPrep в двух сельских школах — Implementation Plan

> **For agentic workers:** использовать superpowers:executing-plans для выполнения по задачам в текущей сессии. Сначала прочитать спецификацию. После каждого блока зафиксировать результат проверки. Этот документ задаёт программу запуска; изменения схемы и контрактов отдельно проектировать в соответствующем блоке после проверки исходного состояния. Не создавать параллельные задачи без отдельного основания.

**Goal:** подготовить проверяемый выпуск для занятий учеников двух сельских школ Актюбинской области и организовать сопровождение пилота.

**Architecture:** сохранить существующий Next.js/Supabase продукт, довести серверное сохранение и права доступа, ограничить школьную программу принятым контентом. Браузер хранит недоверенный черновик с идентификатором операции, сервер подтверждает результат. Состав группы и доступ к программе определяются сервером. Решение по инфраструктуре следует требованиям обработки данных.

**Tech Stack:** Next.js, React, TypeScript, next-intl, Supabase/Postgres/Auth, Vitest, GitHub Actions; текущий хостинг приложения Vercel. Конечное размещение данных пилота ещё предстоит определить.

**Spec:** `docs/pilot/SCOPE.md`; сообщение пользователя от 08.09.2026 о двух сельских школах. Продолжает технический план от 06.09.2026 и заменяет подготовку к презентации подготовкой к занятиям.

**Уточнение пользователя:** сейчас готовим под две сельские школы и оба языка, русский и казахский. Конкретные классы, сроки, предметы, устройства и число учеников будут уточнены позже. До этого не закладывать их в продукт как фиксированные значения.

**Дополнение 08.09:** пользователь поручил начать блок 0; запросил аудит для себя и управления образования, устойчивость бэкенда и полноценный минимальный кабинет учителя. Для графиков выбран Desmos API вместо собственного движка. Требования: [аудит и отчётность](../../pilot/AUDIT_AND_REPORTING.md). Свежие доказательства: [паспорт выпуска](../../pilot/RELEASE.md).

## Правила выполнения

- Статусы различать: найдено в коде / проверено локально / принято на стенде / подтверждено на опубликованном выпуске.
- Один законченный проверяемый таск — один коммит. После изменения кода: `npm run typecheck`, `npm run lint`, релевантные тесты; `npm run build` при изменении маршрутов/сборки и перед выпуском.
- Не редактировать `.env.local`, применённые миграции и согласованные дизайн-токены. Новая схема — новой миграцией с RLS и обновлением `types/db.ts`.
- Сохранять паритет `messages/ru.json` и `messages/kk.json`. Казахские учебные тексты принимает предметный/языковой редактор.
- Проверки доступа и нагрузки проводить на собственных тестовых аккаунтах и синтетических данных. Не собирать детей в текущую production-базу до решения вопросов данных.
- Пилот не допускается по одному зелёному build или успешному показу. Нужны проверки реальной БД, браузера и школьной среды.
- Каждый блок закрывается записью: коммит, окружение, сценарии, результат, оставшиеся ограничения и кто принимает работу.
- Не замалчивать внешние зависимости. Работа над кодом продолжается, пока школы/педагоги/ответственные согласуют свою часть. Согласование нельзя заменять ожиданием заданного числа дней.

## Планирование сроков

Предварительный ориентир: 2–4 недели до контролируемого ученического запуска, если быстро доступны школы, проверяющий педагог и решение по данным. Это оценка, а не обещание. Перенос инфраструктуры, новый способ входа или большой объём казахского контента могут увеличить срок. Точную оценку блока даём после его разведки.

- Первые 1–2 рабочих дня: паспорт выпуска, список несовместимостей, сведения от школ, объём контента и карта данных.
- Далее основной цикл: безопасность/сохранение, группы, программа и работа при слабой связи.
- Завершение подготовки: измерения нагрузки, восстановление, выпуск и репетиция в каждой школе.
- Ученический пилот имеет отдельную согласованную длительность. Четыре недели из презентации автоматически в календарь не переносятся.

Если срок сокращают, уменьшаем темы, группу и необязательные режимы. Не исключаем права доступа, проверку содержания, сохранение и условия работы с данными.
