## Какой результат считаем достаточным для двух школ

Ученик индивидуально входит, получает назначенные проверенные задания на RU или KK, решает и получает подтверждённое сохранение. Повтор запроса не портит прогресс. Учитель видит свою группу и может объяснить, кто приступил, кто завершил и какие темы затрудняют. Команда получает журнал изменений и ошибок. Управлению образования выдаётся воспроизводимый агрегированный отчёт с честными знаменателями. Школа имеет резервный материал и контакт поддержки. Размещение, участие детей и доступы приняты ответственными людьми.

Под «production» здесь понимается настоящий ограниченный школьный запуск с защитой данных и эксплуатацией. Национальный масштаб, все предметы для всех классов и полная LMS — отдельный этап.

## Объём и сроки

Ориентир планирования после чтения кода: **3–5 недель плотной разработки и приёмки одним исполнителем с ревью**, плюс внешние ожидания. Это не обещание даты. Основа release/DB 5–8 рабочих дней; школы/отчёты 5–8; контент/UI/сеть 3–6 с параллельной работой методиста; операции/репетиция 3–5. Путь через новое размещение/перенос Auth может добавить 1–2 недели и зависит от провайдера. После E02 и L02 переоценить по фактической скорости.

Можно раньше показать synthetic демонстрацию teacher и программы; это не разрешение подключить детей без остальных ворот. Если дата школы оказывается раньше — сокращаем число тем, добровольно выключаем AI/Desmos, ограничиваем группы; не снимаем RLS, аудит, backup и проверку контента.

Предположение нагрузки N=60/2N=120 заменяется реальным максимальным числом одновременных учеников после ответа школ. Пока нет даты старта и устройств, нельзя честно назвать точную стоимость инфраструктуры. Бюджет включает hosting + DB/Auth + backups + monitoring + домен + возможную лицензию Desmos; AI в школьном контуре 0 вызовов по умолчанию. Резерв расходов согласуется до активации платного тарифа.

«Потратить все лимиты» не является измеримой сметой токенов: перепланирование и повторный полный контекст обычно дороже выполнения небольших задач. На первые E01/E02 записать число проходов и фактическое потребление доступного окна; дальше прогнозировать по своей статистике. Не обещать процент/цену без измерений и не путать API token prices с лимитами подписки Codex.
