# KT3 RU importer и approved availability — 05.10.2026

Base `55ebbc6`, branch `codex/trusted-practice`. Этот отчёт относится к локальному
изменению, а не production deployment. Владелец сообщил о применении 0035–0037
и передаче translation ZIP другу; независимая hosted сверка ещё впереди.

## Изменение

- Новая 0038: service-only атомарный RU draft import, неизменяемые provenance и
  receipts; replay привязан к полному request, источники/контексты сверяются под
  блокировками. Legacy questions не переписываются, drafts автоматически не принимаются.
- Отдельная service-only приёмка точного version hash с math/language/source refs;
  stale source, карантин и другой hash не допускаются. Приёмка файла последовательна,
  возможен частичный успех; повтор того же файла безопасен.
- Приватный CLI export/import/accept, default dry-run, подтверждение hosted project.
  Source hash вычисляет CLI прежним canonical алгоритмом; SQL сверяет полный exact
  snapshot. Version hash вычисляет SQL из фактически сохранённого JSONB.
- Счётчики и доступность режимов в trusted UI используют approved семьи выбранного
  языка. RPC возвращает только aggregates, без body/ключей/drafts. Ошибки не ведут
  к fallback на legacy банк. Режим flag=false сохранён отдельно для совместимости.
- Общие схемы importer/trusted reader сохраняют ограничения 10 вариантов/пар,
  80 символов ID, 100 блоков, размеры таблиц. Уникальность matching labels и
  дополнительный title block проверяются до импорта.
- CI теперь проверяет весь trusted browser suite, включая teacher report и
  optional Desmos fixture; внешний SDK в тесте подменяется, платных запросов нет.

## Что остаётся до допуска

2. Импортировать фиксированную небольшую RU партию как drafts. Техническая
   проверка четырёх задач не является человеческой приёмкой, курсом или proof
   полного ЕНТ покрытия. Из первых пяти исключена физическая задача, ошибочно
   привязанная к математической теме. У multi-задачи все шесть вариантов верны:
   методическую пригодность проверить отдельно.
3. Получить настоящие review refs; сохранить reviewer/date и документы вне Git,
   принять точные version hashes. Пересчитать hosted inventory/counts.
4. Получить CI и проверенный preview SHA; реальный Auth smoke обязателен, включая
   reload, обрыв сети/повтор ответа и смену pupil/teacher аккаунтов.

   не объявлять capacity или полный production pilot. Не включать trusted flag
