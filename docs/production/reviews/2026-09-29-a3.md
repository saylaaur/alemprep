## Required corrections

### R1 — P1: teacher authorization ignores group assignment

Locations: `0029_pilot_school_access.sql:163–175`, `0030_pilot_assignments.sql:155–165`.

Both public SECURITY DEFINER RPCs accept any active teacher of the same school. Neither checks `group_teachers`. A synthetic teacher with **no assignment to the target group** successfully created an invite and published an assignment (2 participants). This lets a teacher enrol outsiders and schedule work in another teacher's class, contrary to the group-scoped architecture.

Require an active group-teacher link for teachers; allow school-wide action only for the explicitly authorized coordinator role. Define a shared lock order with revocation. Test same-school unassigned/revoked teacher denial as well as cross-school denial.

### R2 — P1: stale invites still enrol into disabled school/group

Location: `0029_pilot_school_access.sql:212–234`.

After issuing a valid invite, setting school to `paused` and group to `archived` still allowed a new student to join and consume a use. The join checks token status and memberships but never active school/group state. Pausing a school therefore does not stop enrolment.

Check and lock current school/group scope and the invite's author eligibility according to the revoke policy. Test pause/archive and revoke races; rejected joins must leave membership, uses and success audit unchanged.

### R3 — P1: concurrent joins bypass the one-active-school rule

Locations: `0029_pilot_school_access.sql:205`, `218–227`.

Locks are per `(actor, operation)` and per invite. Two different invitations for different schools and different operation IDs therefore do not serialize the same learner. The empty membership check sees no other committed membership in either transaction; the unique index is only `(school_id,user_id)`.

Reproduced with two open transactions: `{firstAccepted:true, secondAccepted:true, differentSchools:true}`. Both writes can coexist and commit. Serialize enrolment on a stable actor row/actor-level lock before checking memberships, and enforce the selected student invariant with appropriate database constraints. Test simultaneous joins to two schools, two groups in one school, and competing users on maxUses=1.

### R4 — P1: published programme contents are not immutable

Locations: `0030_pilot_assignments.sql:4–13`, `74–92`.

The item trigger checks only NEW.program_id on UPDATE. Moving an item from an approved programme into a draft programme succeeds; the already published assignment's programme then has zero items. Separately, approved -> draft is unrestricted, so an operator/service write can thaw a programme, edit it and reapprove it under the same ID. Retired programmes are also editable. No row locks synchronize approval and item mutation.

Freeze the historical item set once approved, including retired programmes; check both OLD and NEW parent IDs and serialize programme approval/mutation. Require a new programme identity/version for edits. Enforce approval of the correct locale/purpose/publications in SQL. Test move-out, move-in, demotion, retirement and concurrent approval/mutation on a programme already referenced by an assignment.

### R5 — P2: assignment trigger blocks cancellation and the empty-group path

Locations: `0030_pilot_assignments.sql:94–108`, `198–200`.

Any UPDATE or DELETE of a published assignment raises an exception. `UPDATE ... SET status='cancelled'` cannot work, including for the operator. Publishing an empty group inserts a published assignment and then tries to delete it, hitting the same trigger instead of returning `not-found`. Both reproduced with SQLSTATE P0001. The failing RPC rolls back; this is not an orphan-assignment claim.

Keep scope/programme/window immutable while providing a narrowly authorized, audited cancellation transition. Check empty participant eligibility before publication or use a draft-to-published transaction. Test cancellation/history retention and a safe empty-group response.

### R6 — P2: every 72-hour invite violates its expiry CHECK

Locations: `0029_pilot_school_access.sql:78–81`, `169–174`.

Expiry uses `clock_timestamp()+72h`, while created_at defaults to transaction `now()`. Expiry is slightly later than created_at+72h, so the offered 72-hour option consistently fails with SQLSTATE **23514**, `group_invites_check1`. The existing test exercises only 24 hours.

Use one captured timestamp for creation and expiry; retain the upper bound. Test both accepted durations, including lock wait, and reject null/out-of-range RPC arguments safely.

### R7 — P2: provisioning retry can report success without a coordinator

Location: `scripts/pilot/provision-school.ts:44–68`.

School insertion and coordinator insertion are independent requests. A lost response or process exit after the school insert leaves a partial school; retry sees the same school/name and immediately returns `created:false`, without checking or creating the coordinator. The compensation DELETE is not a transaction and its error is ignored. An existing school also causes a changed coordinator request to be silently ignored.

Use an atomic service-only provisioning RPC with a durable operation identity and full-payload conflict check. Verify/replay the complete school+coordinator result, not merely existence of a school. Test failure/lost response between steps, repeat, and changed payload. This finding is from the concrete code path; no hosted failure was injected.

### R8 — P2: privileged provisioning discards the operator and creates no audit event

Location: `scripts/pilot/provision-school.ts:71–74`.

`operatorId` is parsed then discarded. No operator validation or audit insert occurs for creation of a school or grant of coordinator privileges. The result cannot establish who granted school access, contrary to the architecture's provisioning and audit contract.

Validate the operator through the agreed server/operator boundary; write safe, transactional school/membership events with the provisioning operation. Include audit-write failure rollback and absence of secrets/PII in metadata tests.
