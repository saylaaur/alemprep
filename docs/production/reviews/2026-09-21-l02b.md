## Findings

### R1 — P1: browser DELETE всё ещё изменяет trusted историю

`0028_learning_rewards.sql:252–257` ограничивает INSERT, но оставляет `attempts_delete_own` из 0009 с условием только `auth.uid() = user_id`. Authenticated REST DELETE удаляет integrity=1 attempt, ранее созданную commit RPC. Receipt, score и reward остаются, а aggregates теряют попытку. Удаление неверных ответов позволяет искажать topic accuracy и будущие достижения.

**Воспроизведено:** `tests/db/l02b-review-probes.test.ts`, первый тест: DELETE HTTP 200 возвращает удалённую v1 строку; count после DELETE = 0 вместо 1.

**Исправление:** ограничить DELETE legacy integrity=0 (если до L04 необходим rollback старого пути), проверить все UPDATE/DELETE grants и policies для trusted sessions/attempts. Добавить authenticated и anon REST probes, включая удаление неверного ответа и неизменность receipt/attempt facts.

### R2 — P2: concurrent receipt replay повторно выполняет reward/profile этап

`0028_learning_rewards.sql:71–87`: внешний receipt lookup выполняется до advisory lock. Два одинаковых submit видят отсутствие receipt; второй ждёт во внутреннем L02a, затем получает готовую receipt первого, но обёртка воспринимает её как новую сдачу и снова обновляет profile, session receipt и operation receipt.

**Воспроизведено:** второй probe удерживает advisory lock actor+operation, наблюдает оба ожидающих запроса через pg_locks и отпускает их. Оба ответа HTTP 200 и идентичны, но вместо двух profile UPDATE одной сдачи выполняется три. Дополнительная запись — побочный эффект replay. Двойное XP этим сценарием **не доказано**.

**Исправление:** установить timeout и захватить тот же transaction advisory lock до первого receipt lookup обёртки, либо объединить reward logic с валидатором так, чтобы путь replay завершался до любых новых записей. Прогнать same-operation races, next-day replay и полную неизменность profile/receipts/achievements/audit.

### R3 — P2: migration test требует функцию из 0028 на схеме 0025

Полный migration suite воспроизвёл SQLSTATE 42883: function does not exist на строке 221. Фильтр только нового 0027→0028 теста этого не обнаруживает.

**Исправление:** перенести проверки внутренней функции в тест 0027→0028; проверять anon/authenticated denial и service_role доступ обеих актуальных функций на соответствующей версии схемы.
