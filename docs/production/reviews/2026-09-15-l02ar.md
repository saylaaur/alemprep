## Подтверждённый finding

**P2 — числовой regression-тест не проверяет числа.** `tests/db/learning-rpc-validation.test.ts:295–309`: первые три cases содержат объект, который напрямую передаётся как `graded_items`. RPC требует массив; поэтому возвращает `invalid-input` на внешней форме раньше проверки points/timeSpentMs. Такой тест остаётся зелёным, даже если числовую проверку удалить.

Воспроизведение на local Docker PostgreSQL: перед пробами тела функций сверены с committed 0027. В одной synthetic транзакции временно удалён числовой IF из commit. Все три object cases по-прежнему дают `22023 / invalid-input`; корректно обёрнутый в массив item с `timeSpentMs=7200001` при этой мутации принимается и создаёт attempt/10 XP. На исходной 0027 корректные массивы с fraction, negative и oversized duration отклоняются. Весь fixture и DDL-мутация откатились ROLLBACK; это демонстрация слабого теста, не текущей уязвимости SQL.

Минимальное исправление: cases должны быть массивами `[{...valid, points: 0.5}]`, `[{...valid, points: -1}]`, `[{...valid, timeSpentMs: 7200001}]`; добавить допустимую граничную duration как положительный контроль. Проверить, что временное удаление соответствующей проверки действительно делает тест красным, и восстановить SQL. Для duplicate ID использовать session с несколькими items и совпадающим count, иначе отказ по count не доказывает уникальность.
